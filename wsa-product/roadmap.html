Platform Build Roadmap

Six-step pipeline from discovery to go-live. Timesheet ships first and becomes the permanent foundation for the HR system.

0 · Workshops 1 · DB Design 2 · Infrastructure 3 · Timesheet MVP 4 · HR & Admin MVP 5 · Go-live
We are not simply replacing BQE and Yomly. We are building a modernised, in-house Timesheet and HR & Admin platform — designed around WSA's actual business rules, compliant with UAE Labour Law, and built on a foundation that supports the firm's growth. The system is designed to be AI-ready: the architecture will not prevent AI-assisted features from being introduced in future, but AI is not a driver of the current build.
Step 0 Discovery Workshops Before any design or code
⏱
Timesheet Workshop
Ask about the business need, not the tool. What does a valid working day look like? Who chases who? What feeds payroll? What does the finance team actually do with the export?

Key questions: Approval chain, lock dates, overtime rules, project assignment process, BQE pain points.
🏢
HR & Admin Workshop
Extract business rules (leave types, document requirements, org hierarchy, UAE law obligations) separately from Yomly behaviour. Ask: "If Yomly didn't exist tomorrow, what process would you still need to run?"

Key questions: Leave accrual rules, document retention policy, ticket categories, approval delegations.
raw outputs → formalise into BRD
⛩ Milestone Gate — Business Requirements Document
📄
BRD Drafted
Workshop outputs consolidated into a single formal document. Covers: business objective, MVP scope, functional requirements, business rules (approval chains, leave accrual, labour law), non-functional requirements (performance, security, UAE data residency), assumptions, and open questions.
✅
BRD Reviewed & Signed Off
HR Manager signs off HR requirements · Finance signs off timesheet approval chain & labour law rules · Management signs off MVP scope. This sign-off is the gate. Any scope change after this point goes through a formal change request — protecting the dev team from scope creep.
DB design does not start until this gate is passed
BRD signed → design the data
Step 1 Database Design Derived from workshop outputs · Azure SQL / PostgreSQL
🔗
Shared Entities
Employee, Department, Role, OrgHierarchy, AuditLog. Used by both Timesheet and HR. Designed once, extended — never duplicated.
⏱
Timesheet Schema
Project, SubActivity, ProjectAssignment, TimeEntry, TimesheetPeriod, ApprovalStep. Shaped by workshop rules — not copied from BQE.
🏢
HR Schema
Document, LeaveType, LeaveRequest, TicketCategory, Ticket, EmployeeDocument. Scoped to MVP only — not full Yomly parity.
🗄
Retention & Backup Policy
How long each data type is kept. Soft-delete vs hard-delete. Azure automated backups. Defined before build, not after.
📁
File Storage Design
Azure Blob Storage for employee documents, timesheet attachments. Folder structure, access control, and naming convention defined upfront.
schema approved → provision the environment
Step 2 Shared Infrastructure Azure · Built once · Used by both modules
☁️
Azure Environment Setup
Subscription, resource groups, VNet, App Service / Container Apps. Dev → Staging → Production pipeline. Domain + HTTPS certificate.
🔐
Authentication & SSO
Azure AD / Entra ID integration. Single sign-on for all WSA tools. Integration approach depends on whether AD is local or cloud-synced.
👥
Employee Data Seeding
One-time activity. HR uploads a structured Excel template we provide. Bulk import into the DB on day one. Handles missing fields, duplicates, and data quality before go-live.
👤
Employee Registry
Permanent system. Live DB + admin UI managing ~500 employee records on an ongoing basis. Joiners, leavers, role changes, access revocation. Queried by every module.
📦
Project Data Seeding
One-time activity. Import active projects and sub-activities from BQE or Excel. If export is unavailable, PMs submit a structured template we provide. Must be validated before Timesheet build begins.
📁
Project Registry
Permanent system. Master list of projects, sub-activities, and employee assignments. Shared master data — not a Timesheet feature. Queried by any module that needs project context.
🔑
Role & Permission Engine
Employee, Line Manager, PM, Finance, HR Admin, IT Admin, System Admin. Contextual — same person can be employee in one view, PM in another.
📝
System-wide Audit Log
Every action logged: who did what, when, on which record. Legal requirement. Shared service — not per-module. Tamper-proof, append-only.
📧
Email Delivery Service
Azure Communication Services. Sender domain configured (noreply@wsa-architects.com). SPF/DKIM records. Prerequisite for notification engine.
🔔
Notification Engine
Email + in-app alerts. Triggered by events across all modules. Timesheet reminders, approval nudges, HR ticket updates all run through here.
infrastructure live → build Timesheet MVP
Step 3 · Priority Timesheet MVP Replaces BQE · UAE labour law compliant
⏱
Daily Time Entry
Select project → sub-activity → enter hours. Weekly view. Mobile-friendly. Soft lock (configurable day), hard lock after final approval.
✅
Approval Workflow
Submit → Line Manager → PM → Finance lock. Sequential chain. Delegation when approver is absent. Rejection with mandatory comment.
📊
Reporting & Export
Hours by project, team, period, employee. Export to Excel/CSV for payroll and project costing. All backed by the audit log.
⏰
Reminder Automation
Replaces manual chase emails. Auto-reminders on incomplete timesheets. Escalation if a timesheet is not submitted by cut-off.
⚖️
UAE Labour Law Rules
Min/max hours enforcement, overtime thresholds, grace periods, weekend rules. Non-negotiable compliance layer — needs legal sign-off before any rule is hardcoded.
Timesheet ships → reuse infra for HR

Step 5 Go-live & Cutover Switching 500 employees off Yomly & BQE
🔄
Parallel Run Period
Run new Timesheet alongside BQE for a defined overlap period. Compare outputs. Catch discrepancies before BQE is switched off. Same for HR.
✔️
Data Validation
Verify employee records, project list, and historical data in the new system match source of truth before cutting over.
🎓
Training & Rollout
Role-specific training: employees (time entry), managers (approvals), HR (admin panel). Phased rollout by department reduces risk.
🛑
Yomly & BQE Decommission
License cancellation timeline. Export final archive from both tools before terminating. Confirm data residency is fully in Azure before cut-off.

Open Questions — Must Resolve Before Step 2

These are decision blockers. Each causes design rework if left unresolved at the start of infrastructure setup.

⚠️
Active Directory: Local or Cloud?
Determines the entire Azure AD / Entra ID integration approach. No answer = no SSO design.
⚠️
BQE & Yomly Export Access
Can we get a data export? If not, HR must use the Excel import template we provide. Must be confirmed before Step 2.
⚠️
Payroll Downstream Feed
Does approved timesheet data flow into a payroll system? Which one? Manual Excel export or API connection?
⚠️
UAE Labour Law — Legal Sign-off
Exact overtime thresholds, grace periods, and weekend rules need written confirmation from HR or legal before they are hardcoded.
⚠️
Tech Stack Decision
Frontend framework, backend language, Azure services selection (App Service vs Container Apps, SQL vs PostgreSQL). Needed before Step 2.
